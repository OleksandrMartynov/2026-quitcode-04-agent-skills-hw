# Тест спрацювання скіла `integrating-n8n-webhooks` (бонус E2)

- **Що перевіряємо:** чи модель сама завантажує скіл за його `description` на звичайні запити команди і чи **не**
  завантажує на схожі, але чужі (межі з розділу «Не для» скіла).
- **Інструмент і модель:** Claude Code 2.1.280 у режимі `claude -p`, `claude-opus-5-5`, effort `high`, без
  MCP-серверів; кожен запит — **окрема нова сесія** з кореня репозиторію. Набір 1 — на коміті `8d36554` (скіл v0.2.0;
  його `description` той самий, що в першій версії `970da82`), набір 2 — на `dd340d4` (v0.3.0, той самий `description`).
- **Команда.** Кожну сесію запускає той самий лаунчер `~/ws4-runs/run.sh` (поза репозиторієм), що й проби Task C:
  чисте оточення (`env -i HOME PATH USER LANG`), запит — з файлу UTF-8, як радить walkthrough. Для набору 1 він
  виконав (дослівно з `args=` у `.meta` кожної сесії):

  ```bash
  claude -p --model claude-opus-5-5 --effort high --strict-mcp-config --no-chrome \
    --permission-mode acceptEdits --permission-prompts none \
    --disallowedTools "WebFetch,WebSearch,AskUserQuestion,Edit,Write,NotebookEdit,Bash" \
    --output-format stream-json --verbose --allowedTools "Skill,Read,Grep,Glob" < <запит>.txt > run.jsonl
  ```

  `acceptEdits` лаунчер ставить для всіх прогонів, тож захищає тут лише список заборон. У наборі 1 він забороняв
  `Edit`, `Write`, `NotebookEdit`, `Bash`, але **не** субагентів (`Agent`), `Monitor`, `Workflow`, `CronCreate`,
  `RemoteTrigger`, `EnterWorktree`, `ToolSearch` — вони були в init-події кожної сесії. Жоден файл не змінився,
  проте частково завдяки стриманості моделі (див. нижче n03, n05, n06). Для набору 2 заборонено й їх — див. його
  розділ.
- **Що вважаємо спрацюванням:** у журналі сесії є виклик інструмента `Skill` з `integrating-n8n-webhooks` або
  читання його `SKILL.md`. Журнали `run.jsonl` у репозиторій не комітимо (лежать локально).
- Запити написано так, щоб жоден не збігався із запитом A/B-перевірки (`materials/ab-task.md`), і зберігались поза
  репозиторієм, доки йшли прогони; цей файл написано вже після всіх прогонів.

## Що змінили в `description`

Нічого: промахів не було ні в наборі 1, ні в наборі 2, тож нової версії `description` не знадобилось (версія
скіла 0.3.0 змінилась через чекер і правила, `description` — ні; однаковий блок у `970da82` і `dd340d4`). Межі, які варто було перевірити окремо, вже сформульовано в
`description` явно — «Не для: … коду для вузла Code, експорту JSON воркфлоу, вебхуків інших сервісів (Stripe,
GitHub)…», — і саме на них (n01, n02, n03) скіл не спрацював. Якщо з'являться промахи на реальних запитах команди,
порядок той самий: змінити `description`, підняти `metadata.version`, повторити **всі** 12 запитів у нових сесіях.
